## 二、主要发现

### 发现 1｜总量平稳，内部剧烈换挡

23 个完整月的月量在 **255,364 ~ 348,511 条**之间（极差约 ±16%），看起来非常稳定。但分类型完全不是这样：

- `HEAT/HOT WATER`：峰值 2026-01 **79,928 条** → 谷值 2025-08 **2,929 条**，**27.3 倍**。
- `Noise - Street/Sidewalk`：峰值 2026-07 **25,405 条** → 谷值 2025-01 **3,757 条**，**6.8 倍**，与供暖季方向完全相反。
- 两类合计 1,533,142 条，占全城 20.4%。它们此消彼长，正好抵消在月度总量里。

**含义**：只看总受理量会得出"城市很平稳"的结论；真实的运营压力是结构性、季节性的。

### 发现 2｜"冬季响应变慢 3.9 倍"几乎全是构成效应

全城中位处置时长冬（12–2 月）均值 **16.99 小时**、夏（6–8 月）**4.39 小时**，**3.87 倍**。用直接标准化（把每月"机构 × 类型"的时长分布按全期构成重新加权）分解后：

| 口径 | 冬均值 | 夏均值 | 冬/夏 |
|---|---|---|---|
| ① 实际观测 | 16.99 h | 4.39 h | **3.87×** |
| ② 固定机构构成 | 8.35 h | 6.81 h | 1.23× |
| ③ 固定机构×类型构成 | 7.90 h | 6.85 h | **1.15×** |

**机制**：冬季慢机构 HPD 占比升到 32–37%（夏季约 13%），快机构 NYPD 从约 52% 降到 35%。构造变了，加权平均自然变慢。

**含义**：各机构在自己业务范围内并没有冬季退化，NYPD 全年中位稳定在 1.1–1.5 小时。但这不等于"没有压力"——构成变化本身就是需要提前排班的真实运营冲击。

### 发现 3｜2025–26 冬季冲击链：雪害 ×7.2、坑洞同月 ×5.3，但处置没有变慢

| 类型 | 基期 | 对比期 | 倍数 |
|---|---|---|---|
| `Snow or Ice` | 2024–25 冬 12–2 月 **8,794 条** | 2025–26 冬 12–2 月 **63,722 条** | **7.2×** |
| `Street Condition / Pothole` | 2025-03 **4,313 条** | 2026-03 **22,790 条** | 5.3× |

坑洞爆发当月的中位处置时长 23.7 小时，与常年量级（21.9 小时）基本持平；4–5 月反而降到 17.6–17.8 小时。

**推断（数据内一致，未用外部天气数据验证）**：2025–26 冬季更寒冷多雪，冻融循环加剧路面破损，导致 2026 年 3 月坑洞投诉集中爆发。这是"外部冲击 → 派生诉求"的链条，而不是受理流程变化。

**边界**：只说明记录层面的处置速度没有恶化，不代表养护质量或路面实际状况；且 2026-03 之后坑洞月度基线整体抬升（4,293–11,421 条），未回落到爆发前水平。

### 发现 4｜单个地址贡献全城 2.23% 的记录，高度疑似重复/自动提交

`655 EAST 230 STREET`（BRONX, 邮编 10466）共 **167,703 条**，占全部 7,525,498 条的 **2.228%**。第 2 名地址仅 23,077 条（0.307%）。

证据：

1. **类型高度单一**：99.63% 是 `Noise - Residential`，其中 99.62% 的 descriptor 为 `Loud Music/Party`。
2. **渠道高度单一**：99.63% 经 `MOBILE` 提交，而全城 MOBILE 占比仅 22.14%。
3. **强度不合理**：峰值日 **2025-01-05 单日 4,981 条**（约每分钟 3.5 条）。
4. **小时分布近乎平坦**：各时段占比 3.24%–5.54%；而全城同类噪音投诉在 22–23 时占 10.44%–10.76%，有明显的夜间高峰 + 凌晨低谷。
5. **时间形态异常**：两段爆发（2024-09~2025-01、2025-09~2025-12）后近乎归零，2025-05~08 仅 189 条、2026-01~04 仅 19 条。
6. **确实消耗了公共资源**：这批记录进入了 NYPD 处置流程，中位处置 150.2 分钟，是全城同类投诉（68.5 分钟）的 **2.2 倍**。

**结论（推断，非事实）**：最合理的解释是同一批诉求被反复/自动提交，而不是同一栋楼发生了 16.7 万次独立噪音事件。

**对其它结论的影响**：Noise - Residential 的月度走势被显著抬高——剔除该地址后，该类型 2025-01 峰值从 70,837 条降至 30,847 条（**−56.5%**）；BRONX 全区记录数从 1,664,397 降至 1,496,694（−10.1%），其"居民噪音占比"从 21.9% 降至 13.2%。使用该类型或该区的任何结论都应声明是否包含此地址。

### 发现 5｜机构间处置速度相差约 3 个数量级

| 机构 | 记录占比 | 中位时长 | 30 天内关闭率 |
|---|---|---|---|
| NYPD | 45.23% | 1.34 h | 100.0% |
| DEP | 5.64% | 22.37 h | 95.7% |
| DSNY | 9.12% | 33.80 h | 96.3% |
| DOT | 6.45% | 46.20 h | 89.7% |
| HPD | 21.71% | 87.53 h | 84.6% |
| DOB | 2.91% | 158.87 h | 66.6% |
| TLC | 1.00% | 970.74 h | 28.9% |
| EDC | 0.49% | 6,296.51 h | 1.6% |

**这不是效率排名**：各机构业务性质完全不同（NYPD 现场核查 vs EDC 长期基建项目）。它的价值在于说明——衡量"全城平均速度"时，机构构成会主导结果（即发现 2）。

### 发现 6｜提交渠道持续向线上迁移

`ONLINE` 占比从 2024 年四季度均值 **40.0%** 升至 2026 年 6–8 月均值 **48.8%**；`PHONE` 同期从 **29.9%** 降至 **22.5%**。换用自然年口径并剔除异常地址后，ONLINE 占比为 2024 年 42.6% → 2026 年 49.9%，方向一致、幅度略大。

机构间差异极大：DOB 全期 ONLINE 占比 0%，DOT 约 19%，EDC 约 99%。这说明渠道字段更多反映各机构自身的受理渠道设置，而不是居民偏好。

### 发现 7｜口径陷阱：投诉类型名称在期末被调整

| 机构 | 变化 | 时点 | 证据 |
|---|---|---|---|
| DEP | `Water System` → `Water Maintenance` | 2026-08 | 旧名 2026-07 有 16,261 条、此后消失；新名从 2026-06 的 242 条、2026-07 的 1,892 条升至 2026-08 的 8,925 条 |
| DEP | `Sewer` → `Sewer Maintenance` | 2026-08 | 旧名 2026-07 有 3,131 条、此后消失；新名 2026-07 已并行出现 1,310 条，2026-08 升至 5,060 条 |
| DEP | `Hazardous Materials` → `Hazardous Material` | 2026-07~08 | 旧名 2026-07 仍有 147 条、此后消失；新名从 2026-05 的 5 条升至 2026-08 的 229 条 |
| DEP | `Asbestos` 移交（DEP 停收，DOHMH 继续受理） | 2026-08 | DEP 的 Asbestos 在 2026-07 有 65 条、2026-08 起归零；但 DOHMH 仍在受理，该类型全城 2026-08 仍有 54 条，**并未消失** |

影响范围集中在最后 1–2 个月，本次所有趋势结论均已避开这一段。但这是本数据集最容易被误用的地方——直接按 `complaint_type` 分组画跨期时间序列，会在 2026 年 8 月看到若干类型"突然消失"。

上表最后一行是一个具体的方法教训：只看单一机构口径会把"移交"误判成"停用"；必须同时按类型 + 机构核对，才能区分"类型消失"与"受理方变更"。

## 三、关键限制

1. **未做人口/面积标准化**。区域比较只呈现记录占比，不能读作"各区居民投诉强度"。缺少人口与住房存量数据，且任务未授权引入外部数据。
2. **未使用任何外部数据**（天气、人口普查、预算等）。发现 3 的天气解释是从数据内部一致性推出的合理推断，未经外部验证。
3. **`closed_date` 的语义按机构而异**。NYPD 的 `closed_date` 是警务处置时间；HPD/DOB 等更接近行政结案时间。跨机构比较中位时长只反映"记录层面的时间差"，不等于"问题解决耗时"。
4. **未关闭记录被排除在时长统计之外**（240,304 条，3.19%）。这会系统性低估长尾，且低估幅度随时间接近当前而增大（2026-08 提交的记录仍有 14.27% 未关闭）。
5. **"已关闭"不等于"已解决"**。96.68% 的 status=Closed 中，有记录的 resolution_description 明确写着"未发现违规证据"。本报告不对处置质量作判断。
6. **字段异常已识别但未修正**：1,877 条 `closed_date < created_date`（集中在 DOT Street Light Condition 且 status=Pending）、15,543 条 status=Closed 但 `closed_date` 为空、1 条 `closed_date` 晚于数据截止日。数量级不足以影响总体结论，故未做修补。
7. **异常地址的判定是推断**。数据内证据很强（单日 4,981 条、单一类型单一渠道、全天平坦），但无法从数据本身证明其成因。

## 四、重要假设

| # | 假设 | 依据与影响 |
|---|---|---|
| 1 | 分片文件名标称的时间范围与 `created_date` 实际归属一致 | 已逐分片核对，25 个分片的实际 `created_date` 最小值/最大值均落在文件名区间内 |
| 2 | `unique_key` 唯一即代表无重复记录 | 7,525,498 行对 7,525,498 个唯一值，成立。但"同一现实事件被多次上报"无法从主键识别（见发现 4） |
| 3 | 把 2024-09 与 2026-09 视为不完整月并排除 | 2024-09 缺 9/1–9/6，2026-09 缺 9/6 之后；保留会拉低两端 |
| 4 | 用"机构/机构×类型"构成做直接标准化是合适的分解方式 | 处置时长的机构间差异远大于其它维度；标准化后冬夏差异从 3.87× 降到 1.15×，残差已很小 |
| 5 | 对数分箱（40 箱/十进制数量级）足以刻画时长分布 | 箱宽约 5.9%，对中位数的影响远小于构成效应本身 |
| 6 | 同比使用各 11 个完整月而非自然年 | 数据只有 24 个月，自然年不完整；等长完整月窗口是唯一可比口径 |

## 六、复现方式

在 `D:\项目2\DeepSeek` 下按顺序执行（Python 3.14，依赖 duckdb / pandas / openpyxl / numpy）：

```
python scripts/01_profile.py        # 文件、行数、时间范围
python scripts/02_quality.py        # 缺失率、时间异常、维度分布
python scripts/03_explore.py        # 月度趋势、响应时长、渠道、地理、重复地址
python scripts/04_deepdive.py       # 异常地址剖析、季节性、同比
python scripts/05_deepdive2.py      # 渠道时点分布、响应时长趋势、积压
python scripts/06_diagnose.py       # 冬季变慢的构成分解、队列关闭率
python scripts/07_hpd_boundary.py   # HPD 细分、长龄未关闭、口径边界
python scripts/08_standardize.py    # 直接标准化（标准化的核心计算），输出 outputs/*.csv
python scripts/09_final_tables.py   # 生成看板用全部汇总表 + outputs/headline.json
python scripts/10_anomaly_checks.py # Water System 归零、Street Condition 暴增核查
python scripts/11_taxonomy.py       # 类型口径变更检测、坑洞季节性
python scripts/12_build_excel.py    # 生成 最终成果.xlsx
python scripts/13_verify.py         # 最终复核：独立重算报告引用的 89 个关键数字
```

`01`–`07`、`10` 是探索与诊断脚本（打印核查过程，不产出看板数据）；`08` → `09` → `11` → `12` 是产出链，必须按此顺序执行；`13` 独立重算所有引用数字，可随时单独运行。

`outputs/` 中的 23 个 CSV/JSON 是上述脚本的中间汇总结果，Excel 看板中的每一个数字都能在其中直接查到。

`13_verify.py` 用与主分析不同的写法（字符串切片取日期、逐条独立查询）重算了本说明与看板中引用的全部关键数字，**89 项全部一致**。这是本轮复核的主要依据。
