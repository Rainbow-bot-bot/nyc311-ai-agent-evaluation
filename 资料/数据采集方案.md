# 数据采集方案｜宿主日志与 Telemetry

## 目标

保存每次受控实验的运行事实、工具轨迹、产物和来源哈希。分析数据由 SQLite 重建。

每个正式 run 使用新会话、固定工作目录、统一任务提示和统一输入包。

基础字段：AI、宿主、模型、实验条件、run_id、开始/结束时间、工具调用、Token、费用、产物哈希、原生日志位置与哈希。

未知或宿主未暴露的字段记 `NULL`。

## Run 边界

开始前记录 run_id、AI、host、model、provider、condition、prompt/skill SHA256 和开始时间。

结束后记录结束时间、账单快照、产物哈希和日志哈希。

原生日志按开始时间、工作目录、会话 id 和首条用户提示联合匹配。

正式工作目录：`D:\项目2\<AI>`；公共输入：`D:\项目2\input`。

## Codex

日志：`C:\Users\张尚鹏\.codex\sessions\YYYY\MM\DD\rollout-*.jsonl`。

`session_meta`：session_id、cwd、source、provider。
`turn_context`：model、reasoning_effort。
`token_usage_record`：input/output/reasoning/cache token。
`response_item`：function/custom tool 调用及返回。

整次 run 的 Token 使用最后一条 `thread_token_usage`。
## Claude Code

日志：`C:\Users\张尚鹏\.claude\projects\<encoded-cwd>\<session-id>.jsonl`。

`assistant` 消息提供 model、usage、timestamp；`tool_use` 与 `tool_result` 通过 `tool_use_id` 配对。

DeepSeek / GLM / Kimi / Qwen 经百炼运行时，以 provider usage 作为费用来源。

## Cursor

日志：`C:\Users\张尚鹏\.cursor\projects\...\agent-transcripts\<composerId>\<composerId>.jsonl`。

`state.vscdb` 的 `composerHeaders` 用于核对 composerId、workspaceId 和时间戳。

本机 Cursor 样本可记录工具调用与 turn 状态；Token、cost、逐工具 duration 为空。

Cursor 实际费用来自 Spending/Usage 差额。

## Antigravity

日志：`C:\Users\张尚鹏\.gemini\antigravity\brain\<conversationId>\.system_generated\logs\transcript.jsonl`。

必要时使用 `transcript_full.jsonl` 和 `conversations\<conversationId>.db` 复核。

可记录 step_index、source、type、status、tool_calls、工具结果、子代理和 checkpoint。

本机 transcript 的 Token 与费用字段为空。

## 时间字段

- `wall_seconds`：提示发送前到 Agent 停止后的墙钟时间
- `tool_seconds_observed`：日志有工具起止时间时计算
- `llm_wait_seconds_observed`：provider/宿主有请求起止时间时计算
- `reasoning_tokens`、`thinking_text_chars`、`thinking_seconds` 分开保存
## 费用字段

- `actual_incremental_cost`：run 实际新增扣费
- `estimated_api_equivalent_cost`：按公开/API 目录价换算的等价成本

外币同时保存原币金额、币种、汇率、汇率日期/来源和 CNY。

价格目录：`_实验系统/telemetry/model_pricing.json`。

API 等价成本使用可核的 input / cached input / cache write / output Token。

GPT-6 Astra、Grok 4.6 按逐请求上下文档位；DeepSeek 按忙时/闲时；人民币模型按 CNY 目录价。

## 校准

正式评分前，每个宿主执行一次不计分校准：读取一个文件并产生一个简单输出。

校准检查：
- 会话唯一匹配
- wall time
- 工具计数
- Token/费用来源
- 产物哈希
- SQLite 落库

宿主日志格式变化后重新校准。

## 正式 Run

1. 选择 AI、宿主、模型和实验条件。
2. 保存 billing before，创建 run_id 和 start manifest。
3. 开新会话并发送统一提示。
4. Agent 完成或失败后保存结束时间和 billing after。
5. 定位日志，写入 run / LLM / tool / artifact 数据。
6. 检查时间范围、工具计数、Token、费用方向和产物哈希。
7. 采集通过的 run 进入分析表。
## 解析规则

Codex 工具状态使用结构化 `exit_code`：非零为失败，全部可见值为 0 时为成功，缺少结构化状态时留空。

workspace 快照跳过 symlink / junction 指向的宿主依赖目录。

重解析同一 run 时，parser 先清理该 run 的 tool / artifact / source-log / llm-call 子表，再写入新结果。

## 对照条件

基础组加载统一 `metric-diagnostics`；Evidence-led 组加载协作 Skill。condition 单独记录。

## 可观测性矩阵

|---|---|---|---|---|---|
| Codex | JSONL | 原生 | call/output timestamp | reasoning token | Pro 订阅增量 0 / API 等价另算 |
| Claude Code | JSONL | 本地 usage / provider 对账 | message timestamp | 视日志 | provider usage / 账单 |

| Antigravity | transcript | 空 | 多数工具有起止时间 | 文本可见 | Pro 订阅增量 0 / provider 导出 |

## 操作入口

开始：
`python _实验系统/telemetry/capture_run.py start --ai GPT --host codex --model <model> --condition baseline`

结束：
`python _实验系统/telemetry/capture_run.py finish --run-id <run_id> --status completed`
