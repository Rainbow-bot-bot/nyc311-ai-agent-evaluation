配套成品：`最终成果.xlsx`（13 个工作表的 Excel 看板，无需运行代码即可阅读）。
本文件说明数据口径、主要发现、关键限制、重要假设，以及 Excel 各部分怎么看。

## 1. 数据与口径

### 1.1 数据来源与粒度

### 1.2 时间基准与分析窗口

所有分析以 `created_date`（请求创建时间）为时间基准，解析格式 `%Y-%m-%dT%H:%M:%S.%g`，

| 窗口 | 定义 | 用途 |

| 完整月窗口 | 2024-10-01 ~ 2026-08-31（23 个完整自然月） | 月度趋势图、时段分布 |
| 同比 Y1 | 2024-09-07 ~ 2025-09-06（365 天） | 同比基期 |
| 同比 Y2 | 2025-09-07 ~ 2026-09-05（364 天） | 同比当期 |
| 季节性窗口 | 2025-09-01 ~ 2026-08-31（最近 12 个完整自然月） | 日历月季节性 |
| 时效队列 | `created_date` 在 2024-10-01 ~ 2026-05-31 | 处理时长 |

首月（2024-09）与末月（2026-09）不完整，已从趋势图剔除，但在表格中保留并标注。
同比窗口按数据首日对齐切分以用满全部数据，两窗口天数差 1 天，因此**增长率以日均记录数计算**，
总量差额另行给出。

### 1.3 一处剔除：分析口径 = 7,339,707 条

这是本轮分析中影响最大的处理，Excel「3 数据质量」3.2 有完整证据。

**识别规则（客观、可复现）**：剔除任一 `(incident_address, complaint_type)` 组合，
若其「单日记录数最大值 ≥ 200」。

**阈值依据**：该阈值落在数据的自然断点上。符合条件的组合只有 4 个，单日峰值分别为
4,978 / 2,281 / 1,109 / 272；紧邻其下的最大单日簇是 184 条（Noise - Street/Sidewalk，
一条街道上的多人上报，属合理），而住宅噪音类「单地址两年总记录数」的 99 分位数只有 65 条。
阈值取 200 与取 250 结果完全相同。

**被剔除的内容**：4 个组合共 185,791 条，全部落在布朗克斯东 230/231 街同一街区（邮编 10466），
全部是 `Noise - Residential`，`descriptor` 几乎全为 `Loud Music/Party`，受理机构全为 NYPD，
经纬度与 BBL 各自唯一。最大的 `655 EAST  230 STREET` 有 167,077 条，只分布在 163 个日子里，
有记录日的日均 1,025 条。其中还包含一个只差一个空格的写法变体（`655 EAST 230 STREET`，4,481 条）。

**判断与不确定性**：单栋建筑一天产生数千条噪音上报，与现实事件不可能一一对应，
这是**记录层面**的异常聚集——这一点是事实。但本数据不含上报来源明细或系统日志，
因此**无法确定成因**；自动重复提交、地理编码回落到默认地址、数据生成环节问题都有可能，
这些只作为未验证解释列出，不作为结论。

**为什么必须剔除**：不剔除会同时导致三个错误结论。

| 结论 | 不剔除 | 剔除后 |
|---|---|---|
| 住宅噪音同比 | −2.8%（下降） | **+7.5%（上升）** |
| 住宅噪音季节性（旺淡月倍数） | 2.1（"冬季高峰"） | **1.4（全年平稳）** |
| 布朗克斯住宅噪音集中度指数 | 1.87 | **1.27** |
| 冗余记录占全量 | 20.3% | **18.2%** |
| 布朗克斯记录量位次 | 第 3（22.1%） | **第 4（20.2%）** |

**报告约定**：Excel 中「原始记录数 7,525,498」用于描述数据集本身；
其余全部分析都在 **7,339,707 条**上进行，每页页首都有标注。

### 1.4 其他会影响结论的质量问题及处理

| 质量项 | 规模 | 处理方式 |
|---|---|---|
| 右截断（近月未结案比例升高） | 按创建月看「已有 `closed_date` 占比」：2025 全年稳定在 98%~99%，2026-07 降至 92.3%，2026-08 为 85.7%，2026-09 仅 61.5% | 时效分析只用 2024-10-01~2026-05-31 队列（该队列加权已结案率 97.9%）；不把时长趋势解读为效率变化 |
| `closed_date` 早于 `created_date` | 1,877 条（0.026%） | 逻辑不可能，时效分析中剔除 |
| 处理时长恰为 0 分钟 | 141,007 条（1.92%） | 创建与结案时间戳在分钟精度上相同；多为系统批量结案（DOHMH 占其已结案的 27.4%、DOB 11.9%）；不剔除，但在时效表中单列该比例，提示读数偏快 |
| 处理时长 > 365 天 | 7,781 条（0.106%） | 长尾真实存在（TLC/EDC/DOB）；用中位数与 P90 而非均值 |
| 渠道 `UNKNOWN` | 590,822 条（8.05%） | **非随机缺失**：DOT 交通信号/街灯、DOB 建筑用途/电梯等类型 100% 为 UNKNOWN。渠道分析整体排除 UNKNOWN，只在 ONLINE/MOBILE/PHONE 间计算份额 |
| 问题类型口径切换 | DEP 于 2026-07-29 一次性把 `Water System`→`Water Maintenance`、`Sewer`→`Sewer Maintenance` | 涉及趋势时四类合并看待；季节性表剔除这四类 |
| `borough = Unspecified` | 6,331 条（0.08%） | 行政区分析中排除 |
| 缺 `latitude`/`longitude` | 129,696 条（1.72%） | 未做点位地图分析，不影响结论 |
| `incident_zip` 非 5 位数字 | 8 条 | 可忽略 |

结构上这份数据很干净：主键无重复、时间戳格式统一、`agency`/`status`/`borough`/`complaint_type`
等关键维度无空值。其余高缺失字段（车辆类型 95.6% 空、桥梁名称 99.5% 空等）只与特定业务线相关，
本看板未使用。

## 2. 主要发现

以下每条都标注了时间范围、筛选条件、分母与比较对象。除特别说明外均为分析口径 7,339,707 条。

### 发现 1：一个地址贡献了全部记录的 2.5%，不先剔除它，多个结论会反向

见 1.3。这既是最大的数据质量问题，也是本轮最重要的发现本身——
它直接说明「记录数」与「现实事件数」在这份数据里可以差出一个数量级。

### 发现 2：记录量同比增长 10.7%，接近一半来自天气

- Y1 3,488,583 条（日均 9,557.8）→ Y2 3,851,124 条（日均 10,580.0）；
  日均 **+10.7%**，总量净增 **362,541** 条（+10.4%）。
- 净增长按问题类型拆分（分母 = 362,541）：

| 问题类型 | Y1 | Y2 | 增减 | 同比 | 占净增长 |
|---|---|---|---|---|---|
| HEAT/HOT WATER 供暖热水 | 293,973 | 357,621 | +63,648 | +21.7% | 17.6% |
| Illegal Parking 违章停车 | 550,742 | 608,311 | +57,569 | +10.5% | 15.9% |
| Snow or Ice 冰雪 | 8,808 | 63,938 | +55,130 | +626% | 15.2% |
| Street Condition 路面状况 | 69,370 | 118,298 | +48,928 | +70.5% | 13.5% |

- **冰雪 + 供暖热水 + 路面状况**三类天气敏感型合计净增 **167,706 条，占净增长 46.3%**。
- 同长度冬季窗口（12-01~次年 03-31，各 121 天）对比：全部记录 1,125,791 → 1,324,555（+17.7%）；
  冰雪 8,806 → 63,930（7.3 倍）；供暖热水 197,122 → 232,644（+18.0%）；
  路面状况 23,357 → 45,574（+95.1%）。
- 按机构：HPD +146,949（+19.8%，占净增长 40.5%）、NYPD +79,174（+5.0%，21.8%）、
  DOT +67,712（+32.4%，18.7%），三者合计占净增长 81%。

**证据层级**：三类记录同时同期大幅上升是**已验证事实**。
「2025-26 冬季比 2024-25 冬季更寒冷多雪」是与记录形态一致的**合理推断**，
但本数据不含任何气象观测，无法在此数据内验证，属于**未验证解释**。

### 发现 3：一类「下降」是口径变更造成的假象

DEP 在 **2026-07-29** 一次性切换类型：2026-07-28 当天 `Water System` 仍有 139 条、`Sewer` 33 条；
07-29 起分别降至 1 条与 11 条，07-30 之后恒为 0，而 `Water Maintenance`、`Sewer Maintenance` 同步跳升。

若按单一类型看趋势，会得出「用水投诉在 2026 年 8 月归零」的错误结论。
四类合并后 2026-08 合计 13,985 条，与前几个月同一量级；DEP 机构总量 22,233 条也在正常区间。

同页还列出其他窗口内新增/停用的类型：`Cannabis Retailer`（2025-09 起，由新接入的治安官办公室 OOS 受理，
属真实新增业务线）、`School Maintenance`、`Non-Residential Heat`、`Bike/Roller/Skate Chronic`、
`Construction Safety Enforcement`（窗口内停止出现）。本数据无法区分这些是业务下线、改名归并还是自然消失，
因此不对其做趋势解读。

### 发现 4：机构间处理时长差 3 个数量级

口径：`created_date` 在 2024-10-01~2026-05-31，且 `closed_date` 不早于 `created_date`。

| 机构 | 已结案记录数 | 中位时长 | P90 | 24h 内结案 | 超 30 天 | 0 分钟结案 |
|---|---|---|---|---|---|---|
| NYPD 警局 | 2,617,047 | 1.30 h | 6.4 h | 99.2% | 0.0% | 0.10% |
| DEP 环保 | 332,506 | 23.9 h | 257 h | 50.1% | 2.4% | 6.57% |
| DSNY 清卫 | 564,013 | 33.1 h | 174 h | 39.0% | 2.5% | 0.03% |
| DOT 交通 | 383,434 | 46.0 h | 407 h | 40.4% | 5.8% | 6.95% |
| HPD 住房 | 1,411,167 | 79.0 h | 960 h | 13.5% | 12.9% | 0.11% |
| DOB 建筑 | 176,180 | 231 h | 3,853 h | 25.1% | 37.2% | 11.88% |
| TLC 出租车 | 45,227 | 1,112 h | 4,959 h | 9.3% | 59.9% | 0.01% |
| EDC 经发 | 16,205 | 6,842 h | 8,661 h | 0.0% | 97.4% | 0.00% |

按问题类型，最快与最慢相差约 340 倍：商业噪音 0.90 小时 vs HPD 门窗 308.8 小时。

**不能读作效率排名**：差异首先反映业务性质不同（派警出勤 vs 房屋检查 vs 牌照与执法调查）。
另外「0 分钟结案」比例高的机构（DOHMH 27.4%、DOB 11.9%）中位读数被压低，需连同该列一起看。

### 发现 5：「结案快」不等于「问题解决」

按 `resolution_description` 原文关键词分类 NYPD 全部 `status = Closed` 记录（未分类仅 1.7%）：

| 结案性质 | 记录数 | 占比 |
|---|---|---|
| A 采取行动 / 开票 / 立案 | 899,453 | **28.0%** |
| B 到场未发现问题 / 无需行动 / 当事人已离开 | 2,118,277 | **65.8%** |
| C 无法进入 / 无法核实 | 88,915 | 2.8% |
| D 不属本机构管辖 | 39,403 | 1.2% |
| E 转交其他机构 | 17,731 | 0.6% |
| F/G 其他 / 无说明 | 53,433 | 1.7% |

处置率在类型间差别很大：阻塞车道 38.1%、违章停车 34.1%、住宅噪音 20.1%、车辆噪音 16.1%、
营地（Encampment）仅 0.5%。

**独立印证**：HPD 供暖热水的结案说明中，占比最高的一项（**29.8%**）直接写明
「本条是同楼栋已上报情况的重复，原始投诉将被处理」，另有 15.9% 是「无法进入公寓或楼栋」。
这是机构自己写下的判断，不依赖我们的去重口径。

**证据层级**：分类占比是可回查的**事实**；「快速结案主要来自这种收尾方式」是与数据一致的**推断**；
这些「未发现问题」中有多少是问题已自行消失、有多少是出勤未能核实到，**本数据无法判断**。

### 发现 6：记录数不等于现实事件，约六分之一是重复上报

口径：把「同一 `incident_address` + 同一 `complaint_type` + 同一自然日」视为一个事件簇，
簇内第 2 条起计为冗余记录。

- 7,069,224 条带地址记录 → 5,730,879 个事件簇，冗余 **1,338,345 条**；
  占带地址记录 **18.9%**，占分析口径全量 **18.2%**。
- 分类型冗余率（记录数 > 5 万的类型）：营地 39.4%、供暖热水 32.8%、不卫生环境 31.1%、
  住宅噪音 29.5%、街头噪音 25.1%、违章停车 17.2%（最低）。
- 供暖热水的 32.8% 与 HPD 自己标注的 29.8% 重复结案高度吻合，互为印证。

**这是保守下界**：该口径抓不到跨日的重复、地址写法差异（如上文的空格变体）、
或缺地址（270,483 条）的重复，因此真实重复程度只会更高。

**实践含义**：用记录数比较「哪类问题更严重」时，掺入了约六分之一的重复量，
且重复率在类型间从 17.2% 到 39.4% 不等，不会自动抵消。

### 其他支撑性观察

- **季节性强度差异极大**（最近 12 个完整月）：供暖热水旺淡月 22.2 倍（1 月 79,928 vs 8 月 3,682）、
  路面状况 7.1 倍、街头噪音 6.1 倍；而违章停车 1.3 倍、住宅噪音 1.4 倍、阻塞车道 1.4 倍几乎全年平稳。
  含义：对前者做跨月比较必须对齐同一月份。
- **渠道结构变化**（已排除 UNKNOWN）：网页份额 2024-09 的 44.6% → 2026-08 的 55.7%（+11.1 个百分点），
  电话 32.1% → 23.8%（−8.3 个百分点），移动端 19.0%~24.1% 无趋势。
  位移最集中在 2025-11~2026-01。本数据不含产品发布或客服政策记录，**成因未解决**。
- **行政区问题结构**（集中度指数 = 该问题在本区占比 ÷ 全市占比）：
  布朗克斯在管道 1.75、供暖热水 1.74、不卫生环境 1.62 上高配（房屋维修需求集中）；
  皇后区/史泰登岛在阻塞车道 1.71、废弃车辆 1.74/1.93、路面状况 1.59/2.22 上高配（独栋 + 车行）；
  曼哈顿只在街头噪音 1.48 高配，阻塞车道 0.13 为全市最低。
- **类型集中度**：205 个类型中，前 10 类占 55.8%、前 20 类占 70.2%、前 25 类占 75.3%。

## 3. 关键限制

1. **这是上报记录，不是城市问题普查。** 任何「某问题增加」都同时包含现实变化与上报行为变化，
   本数据无法把两者分开。记录多的地区可能是问题多，也可能是更愿意/更方便上报。
2. **不做人均口径。** 本任务未获授权引入人口或住房存量数据，因此各区绝对记录量不能读作严重程度排名；
   改用结构性的集中度指数。
3. **无外部数据可交叉验证。** 没有气象、人口、住房、执法或系统变更记录，
   因此天气解释、渠道位移原因、类型停用原因都只能停在推断或未解决状态。
4. **异常聚集的成因未知。** 已确认它是记录层面的异常并剔除，但成因无法从本数据判定（见 1.3）。
5. **处理时长有已知偏差方向。** 排除了未结案的 2.1%（使读数偏快）；
   0 分钟批量结案未剔除（也使读数偏快）；两者方向一致，幅度小且已在表中标注。
6. **重复上报是保守下界。** 见发现 6。
7. **首末月不完整。** 2024-09 只有 24 天、2026-09 只有 5 天，趋势图已剔除。
8. **时间精度问题。** 0 时记录占 3.5%，明显高于 1 时的 2.3%，疑为「只填日期」的堆积；
   因此时段分布只作数据形态说明，未用于任何结论。
9. **`complaint_type` 与机构非严格一对一。** 少数类型跨机构（如 Street Condition 对应 DOT 与 DPR），
   表中「主责机构」列仅作参考。

## 4. 重要假设

对口径不明确处所做的最小假设，全部可在脚本中查到：

1. **时间基准取 `created_date`**（而非 `closed_date` 或 `resolution_action_updated_date`），
   因为分析对象是"市民提出了什么诉求"，且 `created_date` 无缺失。
2. **同比窗口按数据首日对齐**（而非自然年或财年），以用满 729 天数据；
   因两窗口差 1 天，增长率用日均。
3. **"事件簇" = 地址 + 类型 + 自然日**。跨日重复、地址写法差异未合并，是刻意选择的保守口径。
4. **异常聚集阈值取「单日 ≥ 200 条」**，依据数据自然断点（见 1.3）。
5. **结案性质分类基于 `resolution_description` 关键词**，规则完整写在
   `06_build_aggregates.py` 的 `OUTCOME` 变量中；未分类归为 F，占 1.7%。
6. **渠道份额排除 UNKNOWN** 而非当作第四类渠道，因其为整类系统性缺失。
7. **季节性用最近 12 个完整月**（2025-09~2026-08），而非跨两年平均，避免月份覆盖不均。
8. **时长用中位数与 P90**，不用均值，因长尾极端值存在。
9. **`borough = Unspecified`（6,331 条）在行政区分析中排除**，占比 0.08%，不影响结论。

## 6. 复现方式

按顺序执行即可从原始 Parquet 重建全部产物（Python 3.14 + DuckDB 1.5.5 + pandas + XlsxWriter）：

```
python 01_explore_schema.py      # 摸底：字段、类型、行数、时间范围、缺失率
python 02_explore_dims.py        # 探索：各维度取值分布与质量问题
python 03_explore_analysis.py    # 探索：同比、渠道、时效、季节性、地理、重复上报
python 04_verify.py              # 验证：区分口径变更与现实变化
python 05_verify2.py             # 验证：同比贡献拆分、结案说明分类
python 06_build_aggregates.py    # 生成 中间汇总/t01~t30.csv（含异常聚集识别与剔除）
python 07_build_excel.py         # 组装 最终成果.xlsx（会 exec 载入 08~11）
python 12_verify_excel.py        # 复核：工作表齐全、关键数字与汇总表一致、加总自洽
python 13_check_layout.py        # 复核：合并单元格无冲突、13 张图表数据区正确
python 15_key_numbers.py         # 打印看板文字用到的全部关键数字，便于核对
```

### 文件说明

| 文件 | 作用 |
|---|---|
| `最终成果.xlsx` | **交付物**：Excel 看板 |
| `分析说明.md` | **交付物**：本文件 |
| `01`~`05_*.py` | 探索与验证脚本，保留以显示结论的来路 |
| `06_build_aggregates.py` | **核心**：唯一做指标计算的脚本，所有口径定义都在文件头注释与 SQL 中 |
| `07_build_excel.py` | Excel 组装框架（格式、表格写入、图表数据区、文本高度） |
| `08`~`11_excel_sheets*.py` | 各工作表的内容与说明文字 |
| `12_verify_excel.py` | 数字一致性复核 |
| `13_check_layout.py` | 排版与图表数据区复核 |
| `14_render_preview.py` | 用 Excel 导出 PDF 做目视复核（自检用） |
| `15_key_numbers.py` | 关键数字汇总打印 |
| `中间汇总/t01~t30.csv` | 30 张中间汇总表，Excel 中每个数字都可在此回查 |
| `out_*.txt` | 各步骤的运行输出，含探索阶段的完整结果 |

`07_build_excel.py` 只做排版与图表，不重新计算任何指标——
Excel 里的每个数字都来自 `中间汇总/*.csv`，而这些 CSV 全部由 `06_build_aggregates.py` 从原始
Parquet 直接算出。
